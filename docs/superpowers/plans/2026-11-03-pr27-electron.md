# PR #27 Electron Chat Integration Plan

> **For agentic workers:** Execute this plan inline in the active checkout. The user explicitly requested desktop reuse of PRs #25–27; no worktree or local Electron window.

**Goal:** Host PR #27's existing shared Chat / Agent workspace in Electron while keeping its web and desktop surfaces on one `apps/studio` implementation.

**Architecture:** Merge PR #27's shared route, chat components, local deterministic agent, and store into the app already used by the Electron shell. Preserve the current PR #26 board editor and PR #25 Home/website-editor host props. Keep chats and board data in their existing renderer stores.

**Tech Stack:** Existing React, TypeScript, Bun/Vitest, DiceBear 9.4.2, and Playwright/Electron E2E. No new native API or provider dependency.

**Spec:** `docs/superpowers/specs/2026-11-03-pr27-electron-design.md`; source: PR #27 head `b125a607a023367813bf4d89fb2ab3ac5c5ed427`.

## Global Constraints

- Preserve the desktop `App` props `onOpenWebsiteEditor` and `active` and the PR #26 board editor route.
- Preserve the interactive PR #26 `FileEditor`; PR #27's read-only `FileViewer` must not replace the desktop board editor.
- Keep `LocalStudioAgent` deterministic and offline; no model, network, cloud, billing, native IPC, or filesystem grant.
- Keep chat storage in renderer `localStorage` and board persistence in the existing `FileStore`.
- Keep the chat route and UI in `apps/studio`, shared by web and Electron.
- Import the shared `chat.css` from both app entrypoints because Electron mounts `App` directly and does not load the web `main.tsx` entrypoint.
- Use the PR #27 DiceBear/Open Peeps dependencies only at the pinned versions and retain `NOTICE` attribution.
- Run all Electron behavior checks in GitHub Xvfb; do not open Electron locally.
- Keep PRs draft; never mark Phase 3/4 `PASS` or merge.

## Review Focus

- A hidden Electron website-editor surface must not capture Chat keyboard actions; cover navigation to Chat and back in desktop E2E.
- Chat generation must not make provider or off-origin requests; assert no HTTP(S) requests during the chat flow.
- Generated documents must be schema-valid and open in the existing board editor; cover the generated preview and Open in Studio action.
- Chat history must survive renderer reload and Electron restart; cover persisted transcript retrieval.
- Free gate, local Pro preview label, malformed chat storage, and cancellation must retain PR #27 behavior; run existing chat tests and representative desktop assertions.
